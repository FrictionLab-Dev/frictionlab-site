Friction Lab

An independent software studio building local-first developer tools.

Friction Lab designs a connected ecosystem of developer tools centered on AI-assisted software engineering, reusable architecture, and native developer productivity — from workflow coordination and codebase memory to terminal navigation and macOS workspace automation.

The goal is not to replace your editor, terminal, or operating system. The goal is to make the spaces between them feel smoother.

Principles

Built with intention.

Every tool in the Friction Lab ecosystem shares the same engineering philosophy.

Local-first

Data and application state stay on your machine. Every tool is designed to be inspectable and to work without a cloud dependency.

Reusable architecture

Shared engineering patterns and modular design across tools, built for deterministic behavior and long-term maintainability rather than one-off features.

Human-reviewed AI

AI-assisted engineering workflows stay reviewable and auditable by default. Automation extends developer judgment — it doesn't replace it.

Relay In development

Local-first autonomous software development platform. Relay turns detailed human-defined product goals into structured, supervised autonomous development. It plans work, coordinates coding agents, governs execution, captures evidence, reviews results, and drives missions toward completion — combining probabilistic AI reasoning with deterministic workflow control.

Friction Lab's flagship product. A native macOS control plane for autonomous software development. Not a chatbot. Not just another coding agent.

Space Buddy In development

Native macOS workspace automation. Space Buddy uses macOS Accessibility APIs to organize, name, jump to, and restore developer workspaces without relying on fragile visual order.

Built around Workspace Profiles, anchor apps, and jump-or-restore workflows for developer productivity. Not a tiling window manager.

Cleanroom In development

A local cleanup utility for development artifacts. Cleanroom scans for build caches, derived data, and other local artifacts that quietly accumulate during development, with an audit-first workflow and no destructive defaults.

Public repository · in development. Initial targets include Xcode DerivedData, DeviceSupport, Archives, simulator artifacts, CMake output, Python caches, .DS_Store, and AppleDouble files.
